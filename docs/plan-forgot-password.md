# แผน: ลืมรหัสผ่าน (ส่งลิงก์รีเซ็ตทางอีเมล) + ช่องอีเมลในหน้าตั้งค่าบัญชี

สถานะ: **ยังไม่ทำ** — ตกลงแผนกันแล้ว รอผู้ใช้สั่งเริ่ม (บันทึก 2026-10-11)

## ที่มีอยู่แล้วในโค้ด
- สมัครสมาชิกเก็บอีเมลไว้ที่ `users.json` → `users[username]["email"]` (`webapp/app.py` route `register`, ใช้ `EMAIL_RE`)
  และกันอีเมลซ้ำ ("อีเมลนี้ถูกใช้สมัครไปแล้ว" — เทียบแบบ casefold)
- เปลี่ยนรหัสผ่าน: `POST /api/account/password` (`change_password`)
- แอดมินรีเซ็ตรหัสชั่วคราว: `POST /api/users/<username>/reset_password` — ตั้ง `must_change_password`
  และเพิ่ม `pw_ver` (ทุกเครื่องที่ล็อกอินค้างหลุด เพราะ `require_login` เทียบ `pw_ver` กับ session)
- บัญชีเก่า (สร้างก่อนมีระบบสมัครเอง / แอดมินสร้างผ่าน `POST /api/users`) **ไม่มีอีเมล**

## 1. ช่องทางส่งอีเมล
- Gmail + App Password ผ่าน `smtplib` (ไม่มี dependency ใหม่) — `smtp.gmail.com:465` (SSL)
- ตั้งค่าใน `.env` บน VPS: `SMTP_USER=...@gmail.com`, `SMTP_PASSWORD=<App Password 16 ตัว>`
  (ตัวเลือก: `SMTP_FROM_NAME=Mee+`)
- ไม่ได้ตั้งค่า = ซ่อนลิงก์ "ลืมรหัสผ่าน?" และปิด endpoint (ระบบอื่นใช้ได้ปกติ)
- ส่งใน thread เบื้องหลัง + timeout ห้ามส่งใน `state_lock` (กฎ CLAUDE.md: ห้ามยิงเน็ตใน lock)
- ผู้ใช้ต้องทำ: เปิด 2-Step Verification ของ Gmail → https://myaccount.google.com/apppasswords → สร้างรหัสแอป
  (แนะนำสมัคร Gmail แยกไว้ส่ง เช่น meeplus.noreply@gmail.com) — เขียนขั้นตอนทีละขั้นให้ผู้ใช้ตอนลงมือ

## 2. หน้าลืมรหัสผ่าน (หน้า login → ลิงก์ "ลืมรหัสผ่าน?")
- กรอกอีเมล → **บอกตรง ๆ ว่ามีบัญชีหรือไม่** (ผู้ใช้เลือกแบบนี้ — พิมพ์ผิดจะได้รู้):
  - มีบัญชี → "ส่งลิงก์ไปที่อีเมลนี้แล้ว (ตรวจในกล่องสแปมด้วย)"
  - ไม่มี → "ไม่พบบัญชีที่ใช้อีเมลนี้ ตรวจตัวสะกดอีกครั้ง"
  - เหตุผล: หน้าสมัครบอกอยู่แล้วว่าอีเมลถูกใช้หรือยัง การซ่อนเฉพาะหน้านี้ไม่ได้ช่วยเพิ่ม
- จำกัดจำนวนครั้ง: ต่อ IP (`client_ip()` — หลัง Caddy ใช้ X-Forwarded-For ตัวท้าย) เช่น 5 ครั้ง/15 นาที
  และต่ออีเมล เช่น 3 ฉบับ/ชั่วโมง กันไล่เช็คอีเมลทีละเยอะ/สแปมกล่องคนอื่น (ดูแบบ `_guest_rate_ok`)

## 3. ลิงก์รีเซ็ต
- token ลงลายเซ็นด้วย `itsdangerous.URLSafeTimedSerializer(app.secret_key, salt="pw-reset")`
  (มากับ Flask อยู่แล้ว) เนื้อหา = `{username, pw_ver}`
- หมดอายุ 30 นาที (`max_age=1800`)
- ใช้ได้ครั้งเดียว: ตอนใช้ เทียบ `pw_ver` ใน token กับของจริง — ตั้งรหัสใหม่แล้ว `pw_ver` +1 ลิงก์เดิมใช้ไม่ได้
- หน้า `/reset?token=...` (template เดียวกับ login แบบ mode ใหม่) ตั้งรหัสใหม่ + ยืนยัน ใช้ `_validate_new_password`
- ตั้งเสร็จ: `pw_ver` +1 (ทุกเครื่องหลุด), ลบ `must_change_password`, เข้าสู่ระบบให้เลย (`_start_session`)
- อีเมลมีชื่อผู้ใช้ด้วย (คนลืมชื่อผู้ใช้จะได้รู้) + บอกว่าไม่ได้ขอเองให้เพิกเฉย
- ลิงก์ในอีเมลใช้โดเมนจริง https (ดูแบบ `_public_base()` ที่ใช้กับลิงก์แชร์)

## 4. ช่องอีเมลในหน้าตั้งค่าบัญชี (ผู้ใช้ขอเพิ่มด้วย)
- ตั้งค่า › บัญชีและแอป: แถว "อีเมล" แสดงอีเมลปัจจุบัน (หรือ "ยังไม่ได้ใส่ — ใส่ไว้ใช้กู้รหัสผ่าน") + แก้ได้
- endpoint ใหม่ เช่น `POST /api/account/email` {email, password}: ต้องใส่รหัสผ่านปัจจุบันยืนยัน
  (กันคนหยิบเครื่องที่ล็อกอินค้างไปเปลี่ยนอีเมลแล้วกู้รหัสเอง), ตรวจ `EMAIL_RE`, กันซ้ำกับบัญชีอื่น (casefold),
  ทำใน `storage.state_lock` + `load_users(fresh=True)`
- บัญชีที่ยังไม่มีอีเมล: ขึ้นจุดเตือนเล็ก ๆ ที่แถวนี้ชวนใส่
- แอดมินเห็นคอลัมน์อีเมลในหน้าสมาชิกอยู่แล้ว (`list_users` ส่ง `email`)

## ทดสอบตอนลงมือ
- sandbox + SMTP ปลอม (`python -m aiosmtpd -n -l localhost:1025` หรือ mock `smtplib.SMTP_SSL`)
- อีเมลมี/ไม่มีบัญชี, token หมดอายุ/ถูกแก้/ใช้ซ้ำ, ตั้งรหัสแล้วเครื่องอื่นหลุด, rate limit, ไม่ได้ตั้ง SMTP = ซ่อน,
  เปลี่ยนอีเมลต้องใส่รหัสถูก + กันอีเมลซ้ำ
